# Dataset A — 2-node fixed-payload n=10 (historical primary campaign)

**Compact:** `01_2node_summary.csv` (12 conditions; jitter / p99 / >100µs% / reconstructed occupancy means).
**Authoritative source of truth (already in this repo, verified, unchanged):**
- `analysis/summary_tables/condition_summary.csv` — per-condition mean/SD/bootstrap CI, all metrics.
- `analysis/summary_tables/run_level_metrics.csv` — every run.
- `analysis/summary_tables/pairwise_contrasts.csv` — primary A60 vs C60 contrast + bootstrap.
- `analysis/summary_tables/occupancy_by_condition.csv`, `load_matching_matrix.csv`, `qc_summary.md`.
- `analysis/scripts/analyze_fixed2_64b_n10.py` — the verified metric module reused by all later datasets.

`01_2node_summary.csv` is a **reformatting (no recompute)** of the `mean` column of the authoritative
`condition_summary.csv` (the `abs_error_gt_100us_rate` was multiplied by 100 to express a percentage).

## Design / method
- A/B/C × baseline/30/60/80 × run1–10 = **120 TRC**. Critical control frame 0x100 (A 8B / B 32B / C 64B),
  5 ms nominal period; PCAN-USB FD Listen-Only.
- **Fixed-payload correction:** an earlier dynamic-payload pilot let `g_seq` reach the CAN payload, so the
  per-strategy write-count changed the payload bit pattern and hence dynamic bit-stuffing — a confound with
  packing. This campaign holds each ID's payload byte-identical; the dynamic set was demoted to a pilot.
- QC (120/120): parse, monotonicity, ID/DLC/payload identity, ESI/error frames, gap>6ms, 9–11ms loss
  candidates — all clean (`qc_summary.md`).

## Key result
- Strict matched primary contrast **A60 vs C60**: reconstructed occupancy A60 63.25 % / C60 63.34 %
  (≈0.09 pp apart); jitter A60 59.76 µs vs C60 22.10 µs → **A60 − C60 = +37.67 µs**, bootstrap CI
  [37.47, 37.86] (`pairwise_contrasts.csv`).
- Full ordering differs by load; 80-target did not pass the strict matching gate, so no strategy ranking
  is asserted there.

## Known limitation (motivating the 3-node work)
In this 2-node setup the CONTROL signal traffic and the dummy/background traffic were generated by the
**same TX MCU**, so pure CAN arbitration/bus contention could not be cleanly separated from same-node
software scheduling / mailbox / release timing. This limitation is what the later 3-node datasets address.
`jitter` here is the PCAN monitor's consecutive-0x100 inter-arrival variation, not one-way latency.
